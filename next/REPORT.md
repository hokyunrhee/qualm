# qualm-next: what was built, how it was measured, and what to ship

qualm's job is to decide, for each changed file, whether an experienced reviewer would ask for the change to be simplified. When the answer is yes, it fails the pull request and tells the coding agent what to fix.

This study built six alternatives to qualm 0.1.1 and measured them against it:
- **dev:** 5,139 file changes from 301 repositories;
- **held-out:** 634 file changes from 125 other repositories, sealed until every candidate was frozen and then opened once.

**Recommendation.** Ship `d-cascade` as **qualm-next** (`next/winner/`). It meets three of the five held-out targets, misses two, and the reasons are below.

There is also a finding the study was not designed to make, labelled post hoc throughout. Most of the ranking gain comes from qualm's own answers (nine of its ten), combined by a model trained on dev instead of reading `push_back` alone. A much smaller change to qualm would capture most of it. It would not capture the perimeter, the localization, or the attacks the winner handles.

Every number here comes from a file in `next/eval/results/`. Section 2 is generated by `eval/report_tables.py` from those files.

## 1. The problem as now understood, and what Phase 0 revealed

**The problem is three problems, and they behave differently.**
1. **Trust.** Can the pull request steer or hide from its own judge? This is deterministic, and every trust attack in the suite is now handled.
2. **Ranking.** Is this file one a reviewer would push back on? This is judgement, and the headroom on real reviewer signal turned out small.
3. **The report.** Can a coding agent act on what it is told? Here the evidence points the right way but is not conclusive.

qualm 0.1.1 treats all three as one question to Jev. Phase 0 showed why that is not enough.

**What Phase 0 revealed** (`data/BENCHMARK.md`, `perspectives/benchmark_summary.md`, Table 2 below):

1. **Reviewers push back on spots, not files.**
   - In the dev sample the perspectives read, six of eight reviewer comments pointed at a single line of an otherwise fine change.
   - qualm's whole-file `push_back` fails 23% of reviewer-comment positives on dev and 19% on held-out.
   - It fails 79% of mechanically injected smells.
2. **The labels a study can get are noisy.**
   - On dev reviewer comments, the label regex and a fresh LLM agree at Cohen's κ 0.449 on the sample, and 0.305 weighted to the population.
   - The LLM read only 75% of strong-wording and 57% of weak-wording comments as requests to simplify.
   - Any classifier's ceiling on natural labels is therefore well below 1.
   - On dev, the natural stratum's PR-AUC is between 0.40 and 0.48 for every candidate run on all of dev.
3. **Size explains as much of natural reviewer signal as qualm does.**
   - A model of size and language only (`n0-size`: added and removed lines, whether the file is new, and the language) scores natural PR-AUC 0.417 on dev, against qualm's 0.405.
   - It pays for that with a 29% false-alarm rate, against qualm's 5.6%.
4. **The trust boundary was open.**
   - qualm reads `qualm.json`, keeps and `.gitattributes` from the pull request it judges. It skips by file name and trusts its cache.
   - 24 of 66 attacks get past it (Table 2l):
     - 17 are a pull request configuring, keeping or hiding itself;
     - 4 are copies;
     - 3 are good changes it wrongly fails.
5. **Dev and held-out differ in ways that move every absolute number.**
   - Held-out prevalence is 38% against dev's 22%.
   - Hard negatives (renames, comment-only edits, reformatting, moves) are 25% of held-out's negatives against 2.4% of dev's.
   - Agent-written approved changes are 48% of held-out's natural negatives against 7%.
   - So only paired differences on the same items are compared. Absolute PR-AUCs are higher on held-out than on all of dev for every candidate.
6. **qualm's threshold was never fitted to labels.**
   - 0.6 came from one unlabelled repository.
   - On dev it gives precision 0.61 and recall 0.31. On held-out it gives 0.84 and 0.33.

**Human adjudication.** 60 items were put to a person through an artifact page: 30 borderline held-out reviewer comments, 15 blind held-out items and 15 dev items. It received no answers.
- The 12 held-out tier-B items stayed unscored, as pre-registered.
- No human-against-label κ can be reported.
- What is reported instead:
  - the regex-against-LLM κ above, on dev only. LLM labels were never used on held-out.
  - the fix loop's blind judge, which got 33 of 34 clean-against-injected pairs and 34 of 34 identical pairs right on held-out (`fixloop/heldout_v1_judge_validation.json`), and 80 of 80 on dev.

Every candidate except the baseline shares one perimeter. It reads policy and attributes from the base branch, checks skips against content, and signs its cache. `b-offline`, `e-spot` and `n0-size` run on the perimeter and core they were trained with (`59b23cd`), so they lack the v3 perimeter fixes, and Table 2l shows it.

How the numbers were made (`eval/PREREG.md`):
- Dev numbers are repository-grouped out-of-fold scores.
- Held-out numbers are the single pre-registered run.
- Intervals are 95% paired percentile bootstraps that resample repositories: 4,000 resamples on held-out, 2,000 on dev.
- A file a candidate could not judge counts as a fail at 1.0.
- `c-llm` was run on dev's 150-item subset only (†). On that subset the baseline scores 0.772 and `d-cascade` 0.836, so its † numbers compare with those, not with the full-dev column.

## 3. The winner, the runner-up, and what each perspective got right

### The winner: d-cascade, shipped as qualm-next

`d-cascade` is the only candidate whose PR-AUC beat qualm's on held-out with the whole interval above 0: +0.043 [+0.005, +0.084]. That was the one confirmatory comparison, fixed before the split was opened. Its gains:
- **Precision** rose, +0.028 [−0.045, +0.113], so precision is not lower.
- **Recall** rose, +0.057 [+0.006, +0.103], at a lower false-alarm rate: 3.6% against 3.8%.
- **At the false-alarm rate matched on dev** (Table 2h), it still has the best precision of any candidate (0.876) and recall +0.049 [+0.000, +0.096].

It is also the best on what the gate is like to live with:
- **Determinism.** 0.55% of file verdicts flip, against qualm's 1.15%. The close-call readings (3, then 7, then up to 11) are what brought it under 1%. Version 2 flipped 1.19% of files on dev (`determinism/d-cascade-v2-perfile.json`).
- **Attacks.** It handles 61 of 66, the most of any candidate. qualm handles 42.
- **Reports.** Findings are 9 lines wide at the median, against qualm's 55. They overlap the reviewer's location at IoU ≥ 0.2 for 49% of failing positives, against 35%.
- **Fix loop.** A fresh coding agent working from its report fixed 11 of 34 held-out items, against 7 from qualm's report. On dev it was 14 of 40 against 10. It blocked fewer clean controls: 5/34 against 9/34, and 7/40 against 11/40.
- **Cost.** It costs twice what qualm does and is still about a hundredth of the cost target. p95 wall time is 23.6 s against a limit of 60.

The packaged version is identical to the frozen one on 100 of 100 dev pull requests (`winner_equivalence.json`). It ran on its own change and failed one file wrongly, a detector whose patterns read as the smells they detect. It passed once a maintainer kept that file from outside the checkout, including with every cache off (`winner_selfrun.json`).

**Why it wins, honestly.** The ablation (Table 2m) says what earns the ranking gain:
- **qualm's own answers in a calibrated model** carry nearly all of it: nine of its ten (all but `direction`) score dev 0.590, against `push_back` alone at 0.524. Post hoc, the same model on qualm's recorded held-out answers scores 0.783, +0.048 [+0.012, +0.080].
- **The rest adds little to ranking.** The comment-stripped view adds 0.01 on dev and nothing measurable on held-out. Detector counts and per-function answers add nothing.
- **The hard negatives carry the pooled gain.** It comes from qualm's own `comments_only` answer used with a negative weight. Both models fail 0 of 96 hard negatives, where qualm fails 4%. Without hard negatives, `d-cascade`'s gain is −0.002 [−0.037, +0.036].
- **On real reviewer signal it ties qualm:** natural stratum +0.004 [−0.047, +0.055].

So `d-cascade` wins on ranking for a simple reason: it uses qualm's other answers, not only `push_back`. It wins the rest of the definition on everything around the ranking:
- the perimeter;
- the close-call readings;
- recall on agent-written smells: it fails 47% of LLM-injected smells, the raw-answer model 32%;
- function-level findings.

### The runner-up: e-spot, and when it would be better

`e-spot` asks Jev about each changed function in reviewers' verbs. Its results:
- **Held-out ranking.** It has the second-best held-out PR-AUC among the frozen candidates: 0.765, +0.030 [−0.021, +0.084], Holm-adjusted p = 1.0.
- **Natural stratum.** It has the best natural-stratum result: +0.030 [−0.046, +0.100], and 0.642 absolute.
- **Localization.** Its findings are the most precise of the Jev candidates: IoU ≥ 0.2 for 56% of failing positives.
- **Cost.** It is cheap: median $0.0004, p95 13.6 s.

It would be the better choice in two situations, if confirmed:
- if agreement with real reviewers on natural changes matters more than pooled ranking, and a future held-out set shows its natural lead is real (the present interval crosses 0);
- if precise locations matter more than recall.

It was not run in the fix loop or for determinism, and its attack record (59/66) is on the older perimeter.

`c-llm` came third on held-out PR-AUC. It is not a runner-up for a gate:
- it flips 4% of files and 17% of pull requests;
- it needs an Anthropic key;
- its dev advantage of +0.078 on the 150-item subset shrank to +0.022 [−0.027, +0.075] on held-out.

Its recall is the highest (+0.139 [+0.080, +0.207]) at a higher false-alarm rate (7.2%). That makes it a good advisory reviewer, not a gate.

## 4. What qualm got right, and what should be kept

- **The ten questions.** They are good, and they carry the signal. Nine of qualm's answers combined reach the winner's held-out ranking (Table 2m). qualm-next asks them unchanged. In the model of qualm's answers alone, the heaviest weights are on `push_back`, `added_impossible_guards`, `new_behaviour`, `grew_a_big_unit` and `added_placeholders`.
- **Jev, not an LLM, at verdict time.** That is why a gate built on it can be deterministic:
  - qualm flips 1.15% of files, the LLM candidate 4–10%;
  - with close-call readings, qualm-next flips 0.55%.

  Keep "no LLM in the verdict".
- **Asking again on close calls.** qualm's idea; qualm-next extends it from 3 readings to a sequence of up to 11.
- **Questions about the diff, not the language.** No parser decides the verdict. qualm-next's lexer only masks comments and finds functions for the report.
- **The guard sentence.** It tells Jev that comments and strings are code to judge. Every prompt-injection attack failed against qualm and every Jev candidate.
- **Fail closed, and three exit codes.** 0 passes, 1 fails, 2 could not judge. qualm-next keeps them and adds two cases to exit 2: `--dry-run`, and files over 1 MB.
- **A conservative gate.** qualm's 0.6 is precise on held-out: 0.84, with a 3.8% false-alarm rate. qualm-next was held to the same precision floor.
- **Keeps, with a reason.** A verdict is an opinion, and a person can overrule it on the record. qualm-next keeps the command and reads keeps from the base branch only.
- **Cost and simplicity.** One request per file, a fraction of a cent per pull request, one binary. qualm-next costs twice as much and is one Python script with no packages to install.

## 5. Risks, failure modes, and what would change the recommendation

**Where the evidence is thin**
- **The gain is concentrated.** On held-out it comes from hard negatives. On real reviewer signal alone, qualm-next ranks like qualm: natural +0.004 [−0.047, +0.055]. A team whose pull requests are mostly ordinary feature work should expect the same ranking as qualm. What it gains is a trustworthy perimeter, fewer flips and findings that name the function.
- **The fix loop is underpowered.** 34 items can show a difference of about 0.26. The observed +0.118 has a lower bound of 0.000: suggestive, not shown.
- **Calibration does not transfer.** Held-out ECE is worse than qualm's: +0.049 [−0.031, +0.097]. Log loss is also worse, +0.047, because the model was fitted at 22% prevalence. Read its probabilities as a ranking, not as frequencies.
- **No human adjudication arrived.** Reviewer-comment labels are noisy (κ 0.45 against an LLM). 12 tier-B items were never scored.
- **Isolation was procedural.** The held-out split was sealed. A scan of 1,976 agents' tool calls found held-out paths only in the 34 agents that built its fix-loop items and in the Phase 4 audit agent that inventoried the leak (`leakscan.json`). Every agent nonetheless shared one filesystem (`data/BENCHMARK.md`).

**How it can fail in use**
- **Copies across files.** Three copy attacks pass with only an advice line, and a fourth (`py_cross_module_copy`) passes with nothing reported. On its own change, qualm-next did not report that its core is a copy of the study's.
- **Code about smells.** Detectors, linters and fixtures containing debug calls on purpose are read as smelly. The first self-run failed `detectors.py`.
- **The contested attack.** In `good_with_legit_markers`, qualm-next fails an impossible guard that really is impossible. Whether that is wrong depends on the reader. The variant with a valid check passes.
- **Jev is a single dependency.**
  - An outage fails every run with exit 2: red builds, not green ones.
  - A new Jev version would need the model retrained on dev. The model is 25 weights, and `train.py` reproduces it exactly.
- **Determinism per pull request.** It is 1.57%, above 1%, because files compound: a pull request with many close calls can still flip. The target was pre-registered per file (`eval/PREREG.md`), and per file it is met.
- **Coverage.** Six languages were trained on, JavaScript thinly (163 items). Extensionless scripts are not judged.
- **Fork pull requests.** They have no key, so the action exits 2 by design. A project that takes outside contributions must decide what that means for it.

**What would change the recommendation**
- **The smaller change.** qualm 0.1.1 with a logistic model over its own answers, plus the base-branch perimeter and the close-call readings on the model's probability. It reached the same held-out ranking post hoc. If it also matches qualm-next in the fix loop and on determinism, it would be the better ship: one request per file, half the cost, no masking lexer, and qualm's Go binary kept. That needs a fresh held-out set: this one has now been looked at for it.
- **A confirmed natural-stratum lead.** If a larger held-out set showed `e-spot`'s natural lead to be real (+0.030 now, interval crossing 0), it would serve teams whose traffic is mostly natural review.
- **Human adjudication.** If a person disagreed with the reviewer-comment labels often, the natural-stratum numbers would move, and with them the case for or against every design that targets them.
- **Cheaper, steadier LLMs.** If an LLM reviewer could be made to flip under 1%, for example by voting over several samples, `c-llm`'s recall would become a gate's recall.
